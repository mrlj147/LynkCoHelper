# 每日提取与现有服务同步

GitHub Actions 每日北京时间 00:37 提取；GitHub 的定时任务可能延迟。现有服务器每 15 分钟检查加密发布文件，在下一次业务任务启动时使用刷新后的配置。

提取依据领克官方版本接口选择上游对应 `apk-vVERSION` APK，并校验 GitHub Release 资产 SHA-256。2026-10-12 已接入上游自动扫描修复，适配 4.2.8 中 `$g` 到 `$f` 的混淆变化；扫描在启动 App 前完成。未能定位密钥类时停止，不猜测类名，也不更新发布文件。密钥不一定每日变化。

仓库仅保存 `tools/appsecret-recipient.pub.pem` 公钥。接收端需要其配对 RSA 私钥（至少 3072 位，文件权限 0600）。请勿将私钥、账号凭证、配置文件或解密结果提交到 GitHub。

接收程序只修改 YAML 中 `lynkco.native_app_key`、`lynkco.native_app_secret`，并同步已存在的对应环境变量覆盖。账号 token、refreshToken、通知地址、模型配置等保留。原子替换时保留文件所有者和权限，备份仅对 root 可读，重复密钥不会重复写配置。

服务使用如下命令，路径可按部署调整：

```sh
/opt/lynkco/venv/bin/python /opt/lynkco/appsecret-updater/LynkCoHelper/tools/appsecret_runtime.py \
  --private-key /etc/lynkco/appsecret-private.pem \
  --config /etc/lynkco/config.yaml \
  --runtime-env /etc/lynkco/runtime.env \
  --state /var/lib/lynkco/appsecret_refresh.json
```

首次部署必须先验证一次真实提取、解密、配置应用和原生只读接口请求，再启用接收 timer。解密校验来源仓库、接收密钥、有效期和 GCM 完整性；失败时保留旧配置。状态文件只记录来源 run、时间和密钥摘要，不记录密钥值。

当前接收程序适用于宿主机 YAML 配置。Docker 服务应挂载配置所在目录，并在下次新进程启动时读取文件；仅挂载单个文件的容器可能继续引用原子替换前的 inode。若凭证通过容器启动环境变量注入，修改宿主机 env 文件不会改变已运行容器的环境，需要按部署方式重新创建容器。

AppSecret 属于应用签名密钥。自动提取不会替代个人账号登录，也不能保证过期账号 token 自动恢复；账号登录仍可能需要验证码。
